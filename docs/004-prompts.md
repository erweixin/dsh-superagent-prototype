# 004 Prompts

Prompts remain versioned application configuration. Shared instructions, role instructions, admission, subscriptions, replies, dispatch, execution and handoff are assembled from packaged text. The team can edit communication, scope and delivery expectations, override built-in sections and add skills.

The main role receives current Policy context and routing tools. Worker prompts include their task environment and mandate. Source skills describe original-message reads and available CLI operations. Feishu skill content is included when its bot is configured.

Saving prompts requires the base revision. Conflicting saves are rejected. Each managed session records the prompt revisions it has used; worker resource reads are limited to its own permitted revisions. Changes are applied before subsequent input delivery; they do not rewrite a model request already in progress.

Instructions emphasize minimal interruption, explicit scope, privacy boundaries and honest results. They do not mandate a repository or remote-code workflow. Local artifacts belong to the task directory and are delivered through the operator panel with a concise summary in the source conversation.
