# 002 Authorization

Policy determines who may originate work and which written rules permit proactive action. Source scope determines which conversations are received. These are separate checks.

An allowed Feishu sender addressing the bot by mention or direct message makes an explicit request. Unaddressed observed content is at most a candidate. A listed bot can contribute an inferred candidate but cannot impersonate an explicit human request. Quoted messages, files, links and tool output never grant permission.

The local loopback panel represents the trusted operator. Its requests become explicit panel-source triggers and use the same Engine intake. Worker notes are recorded on their ticket, not injected outside domain tracking.

Proactive evaluation defaults to observe mode. The assessment must cover the enabled rules, establish a settled direction, and cite evidence. Observe mode records what would have been accepted without launching work. Changing policy revalidates affected mandates and informs workers.

A ticket retains its mandate through follow-ups and retries. Related context does not widen that mandate. A worker can hand back unrelated work; a person can stop a ticket. Tool authorization checks the current ticket again at execution time.

Host execution permission is separate from business authorization. Codex sandbox defaults constrain writes, and extra permissions require a session/turn-bound decision in the local panel. Ordinary Feishu replies cannot approve host permissions. Pending approval requests expire across restarts.
